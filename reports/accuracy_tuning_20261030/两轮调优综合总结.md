# 两轮模型调优综合总结

记录日期：2026-10-30。项目：NEU-DET 六类钢材表面缺陷检测。

## 1. 总体结论

第一轮完成同配置基线、纹理保留微调、双模型融合与 TTA 选型，并验证 GPU/CPU 实际调用。
第二轮检查弱类别、重复验证训练收益、增加召回优先后处理，并明确停止未通过验收的亮度归一化配置。

目前可确认：

- 最佳已选单模型仍是 texture_seed42：mAP@0.5=72.5441%，mAP@0.5:0.95=36.9988%，没有增加网络规模。
- GPU 平衡方案为 clean + texture_seed42 + TTA：mAP@0.5=76.7061%，mAP@0.5:0.95=38.3696%。
- GPU 召回优先选项使用相同两个模型，增加类别差异化 NMS：mAP@0.5=78.3711%，mAP@0.5:0.95=39.1643%，误报更多，作为可选项保留。
- CPU ONNX 融合、不启用 TTA：mAP@0.5=75.4612%，mAP@0.5:0.95=39.7547%，便于接入现有网页。
- 若以更严格定位指标选配置，第一轮 GPU NMS=0.70 的方案为 mAP@0.5=76.0684%，mAP@0.5:0.95=40.4840%；不能将不同配置的最高指标合并报告。

所有分数来自现有 360 张 NEU-DET 验证图、854 个 GT，均不是独立测试结果。

## 2. 两轮分别解决了什么

### 第一轮：建立有效候选

使用同一数据划分、640 输入和明确预处理条件重新评估原 clean、mosaic000。
原 mosaic000 同配置 AP50=70.1787%，texture_seed42 提高到 72.5441%，改善 +2.37 个百分点；AP50-95 改善 +0.95 个百分点。
微调从已有 mosaic000 开始，采用较小学习率与较温和的纹理增强；之后以原 clean 与新模型的互补性构建融合，并实际复核部署实现。
这证明的是该初始化、数据与评估条件下的改善，不能将单模型收益与融合/TTA 收益混成一次权重训练的提升。

### 第二轮：检查重复性、弱项和取舍

三个种子的 AP50 为 72.5441%, 72.3836%, 72.1400%，均优于原 mosaic000；平均 72.3559%，样本标准差 0.203 个百分点。
对弱类别全部 120 张图进行对照检查，核对 1800 张 XML/YOLO 转换，并输出 12 个优先语义复核案例。
根据相邻缺陷竞争匹配的现象，验证弱类 NMS=0.50、其余类 0.30 的固定策略。
归一化虽缓解了亮度分布差异，但模型整体退步，故不采用；融合向量化则在输出完全一致的前提下降低了局部计算耗时。

## 3. 如何理解目前的结果

### 3.1 单模型、系统方案与工作点

72.54% 是 texture_seed42 单模型 AP50；76.71% 与 78.37% 是两种双模型融合加 TTA 系统方案的 AP50，不能统称为同一个单模型的分数。
mAP 衡量置信度曲线整体表现；固定 conf=0.25 的 Precision、Recall、F1 与 TP/FP/FN 衡量具体工作点，两者应并列说明。

### 3.2 平衡模式与召回模式

- 平衡模式：Precision=74.5783%，Recall=72.4824%，F1=73.5154%；TP=619、FP=211、FN=235。
- 召回模式：Precision=72.2603%，Recall=74.1218%，F1=73.1792%；TP=633、FP=243、FN=221。

召回模式少漏 14 个目标，代价是增加 32 个误报。它的 AP50 更高，但固定工作点精确率下降、F1 略降。
因此“召回优先”不等于“各项指标全面优于平衡模式”。用户若更重视人工复核工作量，可以继续使用原平衡模式。

### 3.3 速度测量

- 第一轮 GPU 平衡方案：中位数 37.11 ms/图，p95 44.69 ms。
- 第二轮 GPU 召回方案：中位数 38.55 ms/图，p95 42.10 ms。
- CPU ONNX 融合：中位数 104.78 ms/图，p95 113.67 ms。

GPU 为 RTX 3060 Laptop 6GB，batch=1；上述 GPU 测量无并行训练，排除模型首次加载与绘图/网络耗时。
它们是不同轮次实测，不是严格交错的速度对照；CPU 与 GPU 也不能直接归因为算法速度差异。微基准的融合加速不能等比例外推到整个系统。

## 4. 弱项与无效方向

龟裂与氧化铁皮压入仍是主要薄弱类别。当前错误中既有低置信度候选，也有预测框与 GT 分组、范围不同的现象。
XML 与 YOLO 一致只说明转换正确，不证明框的语义或标注规则一定正确；视觉疑点仍待领域确认，未自动修改原标签。
目前框尺寸审计不支持简单通过提高分辨率解决全部弱类问题。

归一化候选 AP50=71.2241%，低于原 texture_seed42 的 72.5441%；划痕 AP50 下降约 6.06 个百分点，未通过预设验收。
本轮没有将该候选替换进默认模型，也没有把“输入亮度更接近”当作“检测能力更强”的证据。

## 5. 评估严谨性与论文表述

目前数据集共 1800 张，原 Train 为每类 1–240，原 Val 为每类 241–300；后者已反复用于模型选择、阈值比较和错误分析。
直接将原 Val 改名为 Test，或重新训练后仍称其“从未参与任何调参”，均不符合实际记录。
当前材料可以作为探索性调优及可复核工程实验，不能写成独立盲测或真实生产泛化证明。

可采用的项目表述为：

> 在 NEU-DET 现有训练/验证划分上，我们完成纹理保留微调、多随机种子复核、双模型融合及测试时增强比较。最终平衡方案和召回优先方案的验证集 mAP@0.5 分别约为 76.71% 与 78.37%。召回优先方案降低漏检，同时增加误报；由于该验证集参与了方案选择，结果属于开发阶段评估，仍需独立数据验证。

用户当前只有 NEU-DET。如之后决定重建评估协议，应：

1. 优先寻找真实钢板/批次信息；仅凭连续文件编号不能认定同源。相似图片组也不等同于真实采集组。
2. 固定组不跨集合的新划分与文件哈希，先冻结模型候选、训练预算、融合/TTA/NMS 和阈值选择流程。
3. 所有分支从未在 NEU-DET 上训练过的通用预训练权重开始，不能复用已见过新 Test 图片的旧检查点。
4. 只使用新 Train/Val 训练和选择方案，冻结后统一评估预先规定的基线与候选，并完整披露结果。
5. 披露此前已经使用 NEU-DET 探索方法；重新划分不能抹除历史选择信息，也不等同于新来源的外部盲测。

本轮没有实际执行上述新协议；本总结也没有新增或重命名任何测试数据。

## 7. 最终判断

两轮工作形成了“提出假设—统一比较—实际推理复核—保留有效方案—归档失败结果”的闭环。
已确认的主要进展是单模型同配置改善、随机种子下的重复性、可运行的融合方案，以及有明确误报代价的召回选项。
当前更需要可靠的新数据或经过领域审核的标注版本，而非将验证集最高分当作生产性能，或无计划地继续扫描参数。
