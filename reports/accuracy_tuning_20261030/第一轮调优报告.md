# 第一轮模型调优报告

记录日期：2026-10-30。项目：NEU-DET 六类钢材表面缺陷检测。

## 1. 本轮范围与结论

本轮指在已有 `neu_defect_clean` 与 `neu_defect_mosaic000` 基础上开展的本地优化，不包含更早的项目调参历史。
目标是以检测精度为主、兼顾速度：统一评估、验证测试时增强（TTA）与双模型融合、执行一次保留细微灰度纹理的微调，并完成实际推理验证。

本轮取得三项可复核结果：

- 同配置单模型从原 mosaic000 的 70.1787% AP50 提高到 72.5441%，改善 +2.37 个百分点，网络规模不变。
- `clean + texture_seed42` 的 GPU 融合加 TTA，最终实际推理 mAP@0.5=76.7061%，mAP@0.5:0.95=38.3696%。
- 同一组模型的 CPU ONNX 融合、不启用 TTA，最终实际推理 mAP@0.5=75.4612%，mAP@0.5:0.95=39.7547%。

以上均为现有验证集的探索性结果，不是独立盲测或生产线性能证明。

## 2. 数据、基线与评估口径

数据根目录为 `D:\yolov8\NEU-DET`。训练集 1440 张、3335 个标注框；验证集 360 张、854 个标注框。共六类：龟裂、夹杂、斑块、麻点、氧化铁皮压入、划痕。
图片为 200×200 灰度内容；检测网络主输入为 640。

原模型路径：

- `E:\yolo_project\runs\neu_defect_clean\weights\best.pt`。
- `E:\yolo_project\runs\neu_defect_mosaic000\weights\best.pt`。

单模型原生验证统一使用 `imgsz=640`、`rect=False`、`conf=0.001`、NMS IoU=0.70、`batch=8`、GPU、`workers=0`、最多 300 个预测框。
不同推理方案的 TTA、第二次 NMS 等变化单独记录。

四组原模型复核结果如下：

- `clean`：mAP@0.5=69.5242%，mAP@0.5:0.95=35.7834%。
- `mosaic000`：mAP@0.5=70.1787%，mAP@0.5:0.95=36.0526%。
- `clean_tta`：mAP@0.5=71.3542%，mAP@0.5:0.95=37.4058%。
- `mosaic000_tta`：mAP@0.5=70.5601%，mAP@0.5:0.95=35.8615%。

历史报告中约 72.6%/72.8% 的分数与本轮 square/固定形状 ONNX 评估条件不同，不能直接混算提升幅度。
本文的 mAP 是置信度曲线综合指标；后文固定 conf=0.25 的 P/R/F1 是另行统计的工作点，不是同一组指标。
NMS IoU 与预测框/GT 的评估匹配 IoU 是不同参数；工作点计数的匹配 IoU 为 0.50。

## 3. 数据检查

逐文件审计未发现缺失标签、非法归一化框或训练/验证之间完全相同的像素图片。
训练集内部发现 `patches_101.jpg` 与 `patches_105.jpg` 一对完全重复图片。本轮未修改原图片或标签。

## 4. 优化过程

### 4.1 先比较推理增强与原模型融合

TTA 对 clean 与 mosaic000 的收益不同，不能推断“开启 TTA 总是更好”。
原 clean 与原 mosaic000 的融合，在缓存预测统一重算中达到：不启用 TTA 时 mAP@0.5=73.8070%，mAP@0.5:0.95=39.2131%，启用 TTA 时 mAP@0.5=74.6672%，mAP@0.5:0.95=39.5875%。
这些是探索阶段的缓存对照；最终选型以部署实现重新推理全验证集的结果为准。

### 4.2 纹理保留微调

从已经训练好的 mosaic000 权重出发，验证“减弱缩放、平移和亮度扰动，有助于保留细微灰度缺陷纹理”的组合策略。
这不是单个增强参数的纯单变量消融，不能将收益单独归因于 scale 或 hsv_v。

主要设置：

- `epochs=40`、`patience=12`、`batch=16`、`imgsz=640`、`seed=42`。
- `optimizer=AdamW`、`lr0=0.0002`、`lrf=0.1`、`cos_lr=True`、`weight_decay=0.0005`、`warmup_epochs=2`。
- `hsv_h=0`、`hsv_s=0`、`hsv_v=0.15`、`scale=0.15`、`translate=0.05`。
- `fliplr=0.5`、`flipud=0`、`degrees=0`；Mosaic、MixUp、CutMix、Copy-Paste 关闭。
- 使用现有环境与数据划分，原模型不覆盖。

实际训练 19 epoch，第 7 epoch 的训练过程验证 AP50-95 最佳，随后早停。
训练后再次按统一 `rect=False` 配置复核，得到 mAP@0.5=72.5441%，mAP@0.5:0.95=36.9988%。

预设验收要求是：AP50-95 至少超过两个原单模型基线 0.005，且任何类别 AP50 相对原 mosaic000 不下降超过 0.03。新模型通过。
相对 mosaic000 的逐类 AP50 改变为：

- `crazing`：AP50 改变 -0.91 个百分点。
- `inclusion`：AP50 改变 +0.28 个百分点。
- `patches`：AP50 改变 +0.33 个百分点。
- `pitted_surface`：AP50 改变 +2.85 个百分点。
- `rolled-in_scale`：AP50 改变 +4.92 个百分点。
- `scratches`：AP50 改变 +6.72 个百分点。

龟裂仍略有退步，说明整体改善不等于所有类别都改善。

### 4.3 比较新权重的融合搭配

以下八组是缓存预测、相同指标实现下的候选比较；`nms030` 表示先 NMS 0.70、再执行第二次 0.30 NMS：

- `clean_texture_nms070`：mAP@0.5=75.4594%，mAP@0.5:0.95=39.7032%。
- `clean_texture_nms030`：mAP@0.5=73.7240%，mAP@0.5:0.95=37.2471%。
- `mosaic000_texture_nms070`：mAP@0.5=74.2913%，mAP@0.5:0.95=38.8697%。
- `mosaic000_texture_nms030`：mAP@0.5=72.8072%，mAP@0.5:0.95=36.6466%。
- `clean_texture_tta_nms070`：mAP@0.5=76.0731%，mAP@0.5:0.95=40.4646%。
- `clean_texture_tta_nms030`：mAP@0.5=76.7098%，mAP@0.5:0.95=38.3457%。
- `mosaic000_texture_tta_nms070`：mAP@0.5=74.6322%，mAP@0.5:0.95=38.8761%。
- `mosaic000_texture_tta_nms030`：mAP@0.5=73.8188%，mAP@0.5:0.95=36.3357%。

最终选择 clean 与新 texture_seed42 组成双模型，而非默认扩大模型规模或使用三个模型。

## 5. 最终实际推理结果

### 5.1 GPU 平衡工作点

组成：原 clean + 新 texture_seed42，两者均执行原生 TTA；第一阶段 NMS=0.70，第二阶段 NMS=0.30，融合 IoU=0.55。

- mAP@0.5=76.7061%，mAP@0.5:0.95=38.3696%。
- 固定 conf=0.25：Precision=74.5783%，Recall=72.4824%，F1=73.5154%；TP=619、FP=211、FN=235。
- RTX 3060 Laptop 6GB、batch=1，训练结束后单张处理中位数 37.11 ms、p95 44.69 ms。

### 5.2 GPU 定位指标优先配置

保留 NMS=0.70，不执行第二次 0.30 NMS：mAP@0.5=76.0684%，mAP@0.5:0.95=40.4840%。
这一配置的 AP50-95 更高，但不能把它的 AP50-95 与上一配置的 AP50 拼成同一模型工作点。

### 5.3 CPU ONNX 配置

原 clean ONNX + 新 texture ONNX，不启用 TTA，NMS=0.70：

- mAP@0.5=75.4612%，mAP@0.5:0.95=39.7547%。
- 每个 ONNX Runtime session 使用 2 个 CPU 线程，batch=1。
- 单张处理中位数 104.78 ms、p95 113.67 ms。

耗时包括读图、预处理、两个模型、后处理与融合；不包括模型首次加载、绘图保存和网页网络耗时。不同设备和模式间不能直接计算算法加速比。

## 6. 实现与验证

融合使用同类框的置信度加权坐标；每个融合簇最多接受每个模型一个框。双模型共同贡献时使用两源平均分，单模型框分数除以 2。
融合候选分数至少 0.01，最多保留 300 框。顺序 NMS 0.70→0.30 不保证等同于在所有原始候选上直接执行一次 0.30 NMS。

- 缓存 AP 重算与原生 Ultralytics 验证在四组原模型配置上数值一致。
- CPU ONNX 与两个最终 GPU 配置均通过真实推理实现重新处理全部 360 张验证图。
- 原生 batch=8 与实际逐图 batch=1 的结果有微小浮点差异，因此最终报告采用实际推理 JSON。
- API 完成健康检查、真实图片检测、坐标范围、置信度过滤、损坏图片和非法 IoU 检查。
- 未进行云端发布、整套浏览器自动化或生产线验证；DeepSeek 在检测验证中关闭。

软件环境为 Python 3.10、PyTorch 2.5.1+cu121、Ultralytics 8.4.177；未升级现有依赖。

## 8. 本轮结论与边界

本轮确认了新单模型的同配置收益，并得到可实际调用的 GPU/CPU 融合方案。
没有证明生产泛化能力，没有独立测试集，也没有完成标注语义纠正。后续应检查弱类别错误，并确认微调收益是否依赖某一次训练随机性。
