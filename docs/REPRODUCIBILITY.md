# 复核、资产与仓库组织

## 为什么沿用现有仓库

数据、模型研究和部署应用属于同一个项目。保留同一仓库可以连续展示基线、失败实验、协议重建和工程落地；通过目录和文档版本区分阶段，无需复制成多个仓库。只有日后形成可独立维护的研究库或部署服务时，再考虑拆分。

## 文档和数据资产分层

- 根README只展示当前结论和入口；docs保留方案、索引与历史首页；reports及新协议目录保留对应阶段报告。
- 新协议目录内已冻结的代码、配置、数据清单和报告不移动、不改写；根README和docs不是实验冻结的一部分，可以更新展示。
- 完整数据副本、权重、预测缓存及已安装依赖保持本地；Git保留源代码、配置、轻量清单、数值结果和选定展示素材。
- 124张错误对照图约19MB，作为诊断材料保留；大规模原图副本和预测npy缓存忽略。模型权重另行通过Release或其他资产存储管理；本次未创建新版Release。

## 跨机器复现的实际限制

仓库不是包含所有模型和数据的独立安装包。原冻结配置、数据来源及启动脚本含开发机绝对路径；单独克隆后不能承诺一键训练或启动新版模型。

如需新的复现实验，应新建协议版本、配置本机的数据路径和解释器，准备有来源记录的NEU-DET及COCO初始权重，固定软件版本，重新审计和冻结。不能直接改旧freeze/protocol/清单再声称是原来那次实验。

本地已完成的12项训练从COCO通用预训练开始，但C/D从新B检查点微调；不应称为全部随机初始化从零训练。已有模型和ONNX应依据原最终冻结或导出来源记录的SHA256核对。

## 提交和发布

本次仅整理本地README和文档，没有git add、commit、push、创建仓库或发布模型。原本已存在的未提交变动应由项目维护者单独审阅；不会替维护者恢复或删除它们。

提交时应包含README、docs、reports、协议源代码/配置/清单及报告相互引用的图片；检查git status和.gitignore，确保已安装依赖、原始数据、模型副本和临时日志没有混入。

更新GitHub文档不等于更新Render或Streamlit云端。旧在线mosaic000演示与本地GPU融合是独立部署，新模型上线需要单独验证和明确发布。
