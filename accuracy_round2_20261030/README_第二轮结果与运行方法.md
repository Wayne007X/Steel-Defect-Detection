# 第二轮精度优化、错误审计与稳定性验证

日期：2026-10-30。用户已确认目前只有 NEU-DET 数据；本轮没有创建或声称存在独立测试集。

## 本轮结论

上一轮 texture 微调在三个种子上均保持收益，当前最高原生单模型仍选 seed42。
新增类别差异化 NMS 是可选的召回方案；它提升两个弱类别的检出和整体 AP，同时增加误报。原来的平衡方案仍保留。
原始数据、标签、模型目录和现有服务均未被覆盖。

## 1. 三随机种子的微调稳定性

三个实验均从同一 mosaic000 检查点出发，使用相同增强、优化器、最大 epoch=40、patience=12，只改变 seed。
这是微调随机性的重复实验，不是三折交叉验证，也不是三个独立数据集。

- seed 42：mAP@0.5=72.5441%，mAP@0.5:0.95=36.9988%。
- seed 7：mAP@0.5=72.3836%，mAP@0.5:0.95=36.9665%。
- seed 123：mAP@0.5=72.1400%，mAP@0.5:0.95=36.7968%。

原 mosaic000 在相同 square/rect=False 官方评估下 AP50=70.1788%、AP50-95=36.0526%。
三次 AP50 均值=72.3559%，样本标准差=0.203 个百分点。
AP50-95 中位数=36.9665%，超过原基线至少 0.005 的预设中位数门槛，结果通过。
这些种子不是完整 COCO 预训练或原始训练过程的重跑；没有扩大结论到所有训练随机性。

## 2. 弱类别错误审计

为龟裂和氧化铁皮压入的全部 120 张验证图生成了原图/GT/预测对照并查看总览，另列了 12 个优先语义复核案例。
第一轮最终方案的龟裂 FN=90，其中 63 个有同类匹配低分候选；氧化铁皮压入 FN=57，其中 28 个有低分候选、23 个在当前工作点呈现定位偏差。
一些预测的覆盖范围或目标分组与 GT 不同；这些是可见的复核问题，不能自动断言原始标注错误。

全部 1800 张原始 XML 与 YOLO 标签转换一致；本次近似图 pHash 筛查未发现满足阈值的跨划分候选，但不证明完全没有同批次相关性。
框尺寸统计不支持将两个弱类别简单归为小目标瓶颈。

详见 error_audit/README_错误复核与数据补充.md、error_details.csv、annotation_review_queue.csv 及 contact_sheets。
未自动修改任何原始标签。真实数据补充仍需要将来获得新采集图片，并按钢板或批次划分、保留未参与调优的测试批次。

## 3. 可选召回方案：类别差异化去重

依据相邻 GT 与预测框竞争的错误模式，将龟裂/氧化铁皮压入的第二次 NMS 设为 0.50，其余四类为 0.30。
第一阶段官方 NMS 仍为 0.70，融合 IoU=0.55；权重、TTA、置信度聚合和坐标加权规则不变。

实际部署实现已对全部 360 张原始图片重跑，AP50=78.3711%、AP50-95=39.1643%。
RTX 3060 Laptop、batch=1、无并行训练时，预热后单张处理中位数 38.55 ms、p95 42.10 ms；包含读图、预处理、两个 TTA 模型、NMS 和融合，不含模型首次加载、绘图保存或网页网络耗时。
固定置信度 0.25：Precision=72.2603%、Recall=74.1218%、F1=73.1792%，TP=633、FP=243、FN=221。
原平衡方案同工作点：Precision=74.5783%、Recall=72.4824%、F1=73.5154%，TP=619、FP=211、FN=235。
具体代价是多检出 14 个目标，多出 32 个误报；不宣称在全部指标上更好。

同一规则在三个种子上的变化如下：

- seed 42：mAP@0.5 改变 +1.65 个百分点，弱类别平均召回改变 +4.60 个百分点，整体 F1 改变 -0.34 个百分点。
- seed 7：mAP@0.5 改变 +1.90 个百分点，弱类别平均召回改变 +4.81 个百分点，整体 F1 改变 -0.54 个百分点。
- seed 123：mAP@0.5 改变 +1.56 个百分点，弱类别平均召回改变 +5.22 个百分点，整体 F1 改变 +0.45 个百分点。

seed42 通过了预先记录的 AP/弱类召回/F1 损失门槛。seed7 的 F1 降幅略超同样的 0.005 损失参考，因此跨种子结果只支持“AP 与弱类召回方向一致”，不支持“所有种子都全面通过相同验收”。
阈值的折外校准结果也没有证明应替换平衡默认值；没有把全验证集最优阈值包装成独立测试收益。
paired bootstrap 仅用于固定模型、同一验证集内的诊断不确定性；它不包含模型选择和生产分布变化的不确定性。

## 4. 亮度归一化训练实验

观察到氧化铁皮压入训练/验证的平均灰度约 126.43/83.83；按图独立映射自身的 1%–99% 分位后约 122.31/123.63。
归一化不使用拟合得到的训练或验证集统计量。1800 张副本以 PNG 保存，图像尺寸不变，标签逐字节复制，原数据未修改。
从与对照相同的 mosaic000 检查点、seed42 开始，以相同 texture 微调设置训练；唯一主要处理因素是逐图归一化。

结果：未通过预设门槛，不用于替换当前默认模型。
官方归一化验证 AP50=71.2241%、AP50-95=35.4721%；两个弱类平均 AP50 改变 +0.38 个百分点。

- crazing：AP50 改变 +0.58 个百分点。
- inclusion：AP50 改变 -1.83 个百分点。
- patches：AP50 改变 -0.82 个百分点。
- pitted_surface：AP50 改变 +0.03 个百分点。
- rolled-in_scale：AP50 改变 +0.19 个百分点。
- scratches：AP50 改变 -6.06 个百分点。

验收要求：弱类平均 AP50 至少提高 0.03，整体 AP50 至少提高 0.003、AP50-95 不下降超过 0.005，其他类 AP50 不下降超过 0.03。
归一化缩小输入亮度差异不等于已经证明能改善模型，采用与否严格按预设验收记录。
该结论仅适用于本次预处理、初始化和训练设置，不足以判定所有亮度归一化方法均有效或均无效。

## 5. 推理代码与速度

融合中的逐簇 IoU 计算改为向量计算，保持相同匹配顺序与计算规则。
六组配置、每组 360 张的输出框、类别、分数与独立旧实现逐元素完全一致，共 2160 次逐图验证通过。
evidence/fusion_vectorization_verification.json 记录融合步骤微基准；不能把这个局部耗时改善直接当作整个系统的加速比例。
GPU/CPU 总耗时需按设备、模式和当时并发条件读取实际测量记录。

## 运行方法

进入本升级目录。平衡 GPU 模式保持原参数：

```powershell
& 'E:\yolo_workspace\Scripts\python.exe' .\predict_accuracy.py 'D:\yolov8\NEU-DET\validation\images\crazing\crazing_241.jpg' --tta --device cuda:0 --conf 0.25 --iou 0.30
```

召回优先模式增加 --adaptive-nms（该标志覆盖全局 --iou，使用固定的六类阈值）：

```powershell
& 'E:\yolo_workspace\Scripts\python.exe' .\predict_accuracy.py 'D:\yolov8\NEU-DET\validation\images\crazing\crazing_241.jpg' --tta --device cuda:0 --conf 0.25 --adaptive-nms
```

输出 JSON 会记录实际 class_nms，结果图片和 JSON 写入 accuracy_predictions。
如需 CPU 网页版，分别启动 run_accuracy_api.ps1 和 run_accuracy_frontend.ps1；沿用平衡 ONNX 融合模式，不会暗中打开类别阈值覆盖或 TTA。
CPU ONNX 方案的原全量 AP50=75.4612%，本轮权重不变。
本轮沿用上一升级包的 8001/8502 端口；如上一升级版仍在运行，先在对应终端按 Ctrl+C 结束，再启动本轮入口。

模型：models/texture_ft_best.pt 与 .onnx。实验重复权重归档在 experiments/texture_seed7 和 texture_seed123，不参与运行时三模型融合。
本包复用 E:\yolo_project 原 clean 权重及原 API/Streamlit 源文件；原服务 8000/8501 不变，新入口采用 8001/8502。
