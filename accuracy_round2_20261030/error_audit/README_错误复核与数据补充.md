# 龟裂与氧化铁皮压入：错误复核与数据补充

本目录对应第一轮最终 GPU 方案：clean + texture_seed42，原生 TTA，置信度 0.25，顺序 NMS 0.70→0.30，匹配 IoU=0.50。

## 已完成的检查

- 对全部 360 张验证图片重算了一对一匹配，TP=619、FP=211、FN=235，与第一轮实际部署实现一致。
- 为两个弱类别全部 120 张验证图片生成了原图、GT、预测三栏对照，并检查了十张总览图。
- 核对了全部 1800 张图片的原始 XML 与 YOLO 标签，未发现转换内容或图片尺寸不一致。
- 用 63 位感知哈希筛查了同类别 train/val 图片；当前 Hamming≤6 筛选下没有候选。这不能证明不存在同批次相关性、近似裁剪或其他数据泄漏。

## 主要错误模式

龟裂：90 个漏检中，63 个存在同类 IoU≥0.50、但分数低于 0.25 的候选；22 个在当前工作点呈现定位偏差，4 个同时存在低分与定位偏差，1 个呈现类别混淆候选。

氧化铁皮压入：57 个漏检中，28 个存在低分候选，23 个呈现定位偏差，5 个同时存在低分与定位偏差，1 个存在相邻 GT 竞争匹配。

这些分类是根据分数和框重叠定义的诊断模式，不是物理根因证明。预测可能与标注对同一缺陷区域的分组、范围不同，仍需结合领域规则判断。

龟裂验证框的宽高分别中位数约 141.5/68 像素，没有面积小于 32×32 像素的框。氧化铁皮压入对应约 78.5/85 像素，只有 1 个框面积小于 32×32。大标注框里仍可能含有细微纹理，因此这些结果只能说明“单纯提高输入分辨率”目前缺少充分依据。

## 阅读对照图

`images` 内有全部 120 张单图对照；`contact_sheets` 内每页最多 12 张，按漏检和误检严重程度排序。

- 左栏：原图。
- 中栏：GT；绿色框在当前配置下已匹配，红色框漏检。
- 右栏：当前阈值下的预测；青色框已匹配，橙色框误报。
- `error_details.csv`：每个 FN/FP 的分数和重叠模式。
- `per_image.csv`：每张图片的 TP/FP/FN。
- `annotation_review_queue.csv`：优先复核的 12 个具体案例、原 XML/标签路径及待回答的问题。

优先复核案例是视觉疑点，不是已确认的标签错误。本轮没有自动修改任何原始标签，也没有为了提高验证分数改变验证集标注。

## 如果确认标注需要纠正

1. 先明确相连裂纹或分散压入区域应如何划分为目标，框应包含哪些可见区域。
2. 对训练和验证执行相同规则，建立独立数据版本，保留每次修改前后的标签、原因和审核人。
3. 所有基线和候选在同一份修订版数据上重新评估；不能把旧标签下的基线与新标签下的模型分数直接比较。
4. 修改过或反复查看过的验证图，仍属于开发评估数据，不能宣称为独立测试集。

## 新数据的收集方式

需要真实来源的新图片才能继续建立独立测试集。当前项目里的示例图、截图以及已参与调参的 NEU-DET 图片，没有被重新包装为独立测试数据。

建议同时保留以下信息：原始图片文件名、钢板或样本编号、采集批次、相机、照明条件、采集时间、标注版本、审核人。

补充优先级：实际漏检的弱类别、容易误报的正常纹理、不同照明下的同类缺陷，以及原数据中没有覆盖的缺陷形态。正常背景也应标注并纳入误报评估。

按钢板、连续采集序列或批次分组划分 train/val/test。同一来源的相近图片放在同一组；先固定划分再增强。新测试批次应保持封存，训练和阈值选择结束后再评估。当前文件中没有编造采集批次或新测试样本。
